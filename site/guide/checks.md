# الفحوص

> لمن احمرّ عنده فحص، أو يضيف فحصًا، أو يراجع طلبَ دمجٍ يمسّ الموقع.
> ← [فهرس الموقع](../README.md)

## أي فحص أشغل

| عدّلتَ… | شغّل |
| --- | --- |
| أيَّ شيءٍ في `site/` | `python tests/docs/check_site.py` |
| المسرد أو الاختصارات | ومعه `python tests/static/lint_patchers.py` |
| صفحاتِ `content/` | ومعه `python tests/docs/check_drift.py --offline` |
| المولِّدَ دون قصد تغيير المخرَج | ومعه [أدوات الإثبات](#أدوات-الإثبات) |
| حارسَ الموقع `site_guard/` | ومعه `python tests/docs/test_site_guard_names.py` |

ومتى احمرّ فحص:

1. ابحث عن وسمه في الرسالة، مثل `[OUT-02]`، ثمّ في الجداول أدناه.
2. الرسالةُ بلا وسم؟ ابحث عن نصّها في `tests/docs/site_guard/`.

## حارس الموقع check_site.py

يبني الموقعَ في `site/public/` ثمّ يفحصه، وهو ما يحجب النشرَ وCI.

```bash
python tests/docs/check_site.py              # يبني ثمّ يفحص
python tests/docs/check_site.py --no-build   # يفحص site/public/ كما هو، كما يفعل deploy_site.sh
```

- **العدد والبصمة:** يطبعهما في آخره، ويقارنهما `same_guard.py` بين فرعين.
- **الأقسام:** في `tests/docs/site_guard/`، مرتّبةٌ في قائمة `SECTIONS` بـ`check_site.py`.
- **في CI:** يعمل في `build-matrix.yml` و`docs-pages.yml`، ومعه `test_check_site_nobuild.py`.

### بنية المولد والمخرج

الملفّ: `site_guard/out.py`

| الوسم | يمسك |
| --- | --- |
| DET-01 | بناءً يقرأ اللحظةَ أو الجهازَ أو ترتيبَ القرص، أو بايثونَ آخرَ في جذر `site/` |
| GEN-01 | وحدةً في `sitegen/` لا يبلغها البناء، أو حلقةَ استيراد، أو `__pycache__` في المصدر |
| OUT-01 | ملفًّا قديمًا نجا من بناءٍ سابق، أو محوَ مجلّدٍ ليس للمولِّد |
| OUT-02 | مخرَجًا في `site/public/` يخالف بناءً نظيفًا في مجلّدٍ مؤقّت، بالبايت |
| OUT-03 | ملفًّا في المخرَج بلا مصدرٍ ولا إعلان، أو صفحةً تحمّل من أصلٍ آخر |
| MIN-01 | تجريدَ تعليقاتٍ أسقط شيئًا غيرَ التعليق |
| MIN-02 | ورقةَ أنماطٍ أو سكربتًا تجاوز سقفَه المضغوط في `_GZ_CAP` |

ومعها بلا وسم: الملفّاتُ الإلزاميّة، والمراسي التي يبحث عنها `site.js`، وجزيرةُ البيانات، والروابطُ المطلقة، والأصولُ المحلّيّة الغائبة.

## حراس من خارج الموقع

في `tests/static/lint_patchers.py`، ويعمل في CI بـ`ci.yml`:

| الوسم | يمسك |
| --- | --- |
| ON-03 | نسخةً محفوظةً من المسرد أو الاختصارات في امتداد الترحيب، أو خطوةَ حزمٍ لا تولّدها من `site/data/` (‏`build/lib/help_data.py`) |
| GLS-02 | ألفاظًا ممنوعةً في المسرد زادت في حزمة اللغة المورَّدة |
| PKG-01 | منصّةً في `data/site.json` بلا فرع تغليفٍ في `package_assets.sh` أو بلا صفٍّ في `build-matrix.yml`، أو العكس، فتحمرّ في CI لا عند الزائر |
| WEB-10 | سكربتًا داخليًّا في المخرَج، تحجبه سياسةُ CSP والصفحةُ تبدو سليمة |

ومعها فحصُ المسرد في `content/`: بديلٌ ممنوعٌ في صفحةٍ يحمرّ.

## أدوات الإثبات

متى: تغييرٌ يُفترض ألّا يغيّر شيئًا، كإعادة تنظيمٍ أو تقسيمٍ أو نقل.

```bash
python tests/docs/same_output.py origin/main   # المخرَجُ مطابقٌ بالبايت لـ main؟
python tests/docs/same_guard.py origin/main    # الحارسُ يفحص ما كان يفحصه، عددًا وبصمة؟
node tests/meta/mutation.mjs --guard check_site --dump-failures <مجلّدٌ فارغٌ أو جديد>
                                               # كلُّ مُصابٍ يحمرّ، وبالسبب نفسه؟
```

- **المخرَج:** يبني `same_output.py` الطرفين مرّاتٍ ببيئاتٍ مختلفة. فرقٌ مقصود يُذكر في طلب الدمج باسم ملفّه.
- **المُصابات:** يزرع `mutation.mjs` أعطابًا من `tests/meta/mutants.json`، ويشترط أن يظهر نصُّ `expect` في سطور فشل الحارس.
- **السبب:** شغّل `--dump-failures` على الفرعين بمجلّدين، ثمّ قارنهما. التطابقُ يعني أنّ كلَّ مُصابٍ يحمرّ للسبب نفسه.

## أضف فحصا

متى: عطبٌ ممكنٌ لا يمسكه فحصٌ قائم.

1. اختر وحدةً في `site_guard/` بحسب موضوع الفحص. وحدةٌ جديدة تُستورد في `check_site.py`، وتُضاف إلى `mods` في `_layout()`، وإلّا لم يرها [GRD-01](#بنية-الحارس-نفسه).
2. اكتب القسمَ دالّةً `sNN_<الوسم>_<المعنى>(c)` بالرقم التالي لآخر قسم، وأضفها آخرَ `SECTIONS`.
3. ضع الوسمَ في كلّ رسالة فشل، مثل `[OUT-02]`.
4. أضف مُصابًا إلى `tests/meta/mutants.json` بحقوله: `id`، و`guardFile`، و`guard`، و`file`، و`old` (فريدٌ في ملفّه)، و`new`، و`expect`، و`why`. والحارسُ أخضرُ قبل الزرع.
5. شغّل:
   ```bash
   python tests/docs/check_site.py
   python tests/docs/test_site_guard_names.py
   node tests/meta/mutation.mjs --only <id المُصاب>
   ```
6. أضف الوسمَ إلى جدول وحدته في هذه الصفحة، ولو كان من عائلةٍ قائمة.

تحقّق: الحارسُ أخضر، والمُصابُ الجديد أحمرُ بنصّ `expect`.

## راجع طلب دمج

متى: طلبٌ يمسّ `site/` أو حارسَه.

1. **فحوص CI** خضراء كلُّها.
2. **أيُّ فرقٍ في المخرَج** مذكورٌ في الطلب باسم ملفّه، ومثبَتٌ بـ`same_output.py`.
3. **لكلّ فحصٍ جديد** مُصابٌ في `mutants.json`، وسطرٌ في هذه الصفحة.
4. **تحديثُ ترجمة** معه `translated_at` و`source_sha` جديدان.
5. **ملفٌّ أو وحدةٌ جديدة** لها صفٌّ في [خريطة الملفّات](../README.md#خريطة-الملفات).
